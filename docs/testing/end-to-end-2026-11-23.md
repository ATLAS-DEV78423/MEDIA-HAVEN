## Full download path — real qBittorrent, local torrents

Nothing was downloaded from the internet. Two tiny torrents were created with
Python's standard library and served by a local tracker at
`127.0.0.1:6969`. Two throwaway qBittorrent containers ran on an isolated
Docker network: one seeding, one downloading through our app.

### Safe torrent (`sample.mkv`, 86,016 bytes)

1. `POST /host/acquisition_add` with the magnet went through the app's signed
   API, not directly into qBittorrent.
2. The app added the task paused, read the declared names, saw only
   `sample.mkv`, and resumed it.
3. qBittorrent completed the download from the local seeder.
4. Observed: qB state `stalledUP`, progress `1`, `completed=86016`.
5. Observed file in the download folder: `sample.mkv`, 86,016 bytes.

Result: **PASS**.

### Unsafe torrent (`installer.exe`, 77,826 bytes)

1. The same app API received the magnet for a torrent containing an `.exe`.
2. The app added it paused, read the declared names, and rejected it.
3. Observed HTTP response: `400 invalid_request`, fixed message
   "The acquisition request was rejected."
4. Observed qBittorrent task list: only the earlier `sample.mkv` task; no
   `installer.exe` task remained.
5. Observed files in the download folder: only `sample.mkv`. No `.exe` was
   written.

Result: **PASS** — the executable guard worked with a real qBittorrent.

## Bug found by the live test

`QbClient::resume` called qBittorrent's `/api/v2/torrents/resume`, which returns
404 on qB 5.3. The correct endpoint is `/api/v2/torrents/start` (live-checked:
404 vs 200). Every clean torrent was therefore being rejected. The endpoint was
changed and the installer rebuilt. This bug was invisible to unit tests because
they used a fake HTTP seam.

## Live API security check (same session)

Unauthenticated, wrong-token, stale-timestamp and bad-signature requests were
rejected with 401. Malformed JSON and unknown fields were rejected with 400.
`/artwork/not-a-hash` returned 400. A hostile origin received no CORS header.
A body over 1 MiB returned 400. No response contained a key, address or path.
